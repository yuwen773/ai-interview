## 五、高风险坑点清单

### 5.1 Top 3 技术风险

| 序号 | 风险点 | 风险等级 | 影响范围 | 应对策略 |
|------|--------|----------|----------|----------|
| R1 | Spring AI 2.0 API Breaking Changes | 🔴极高 | 15+ Service 类需重构 | 建立 Adapter Pattern，分模块渐进升级 |
| R2 | LLM Provider 配置热更新线程安全 | 🔴高 | 多租户配置不一致 | CopyOnWrite + 版本号 + 灰度发布 |
| R3 | 语音面试 WebSocket 状态一致性 | 🔴高 | 断线重连状态丢失 | 心跳 + ACK + Redis 持久化 |

### 5.2 风险详细说明

**R1: Spring AI 2.0 API Breaking Changes**

```
问题：ChatClient、PromptTemplate、ToolCallback API 不兼容
影响：约 15+ Service 类涉及 AI 调用代码需重构
第三方：spring-ai-alibaba-starter-dashscope 可能尚未支持 2.0
```

**R2: LLM Provider 配置热更新线程安全**

```
问题：配置变更时，并发请求可能获取不一致配置
场景：T1 管理员更新 API Key，T2 请求 A 获取新 Key，T3 请求 B 获取旧 Key
方案：CopyOnWriteMap + 版本号 + 灰度发布 + ApplicationEvent
```

**R3: 语音面试 WebSocket 状态一致性**

```
问题：断线重连后状态丢失、三轮对话状态不一致
场景：用户断线重连后会话 ID 相同但状态丢失
方案：心跳（30s）+ 连续 3 次失败判定断开 + 消息 ACK + 5 分钟超时清理
```
