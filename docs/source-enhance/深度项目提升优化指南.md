## 一、双项目架构对比总览

### 1.1 核心差异矩阵

| 维度 | interview-guide (源) | ai-interview (目标) | 升级优先级 |
|------|---------------------|---------------------|-----------|
| 构建工具 | Gradle (单模块) | Maven (多模块) | 低 |
| Spring Boot | **4.0** | 3.5.8 | 中 |
| Spring AI | **2.0** | 1.1.2 | **高** |
| Java 版本 | 21 (toolchain) | 21 | - |
| AI Provider | **多Provider动态注册** | 单一DashScope硬编码 | **高** |
| 模块完整性 | 语音面试、日程管理 | 缺少语音面试 | **高** |
| Advisor架构 | 可插拔Advisor链 | 基础结构化输出 | 中 |
| 数据库迁移 | JPA ddl-auto | Flyway | 低 |
| 虚拟线程 | 全面启用 | 已启用 | - |

### 1.2 架构相似性（兼容基础）

两个项目**同源架构**，具备无缝兼容的技术基础：

```
相同分层模式     → Controller → Service → Repository
相同异步模式     → Redis Stream + 重试机制
相同跨切面机制   → RateLimitAspect + GlobalExceptionHandler
相同技术选型     → PostgreSQL + pgvector + Redis + Tika + iText
相同命名规范     → XxxEntity / XxxDTO / XxxRequest / XxxResponse
```

### 2.5 【中优先级】Advisor 可插拔架构

- `SafeGuardAdvisor` - 敏感词过滤
- `SimpleLoggerAdvisor` - 日志增强

**升级思路**

```java
@Configuration
public class AdvisorConfig {
    @Value("${advisor.tool-call-enabled:true}")
    private boolean toolCallEnabled;

    @Value("${advisor.memory-enabled:true}")
    private boolean memoryEnabled;

    public ChatAdvisor[] buildAdvisors() {
        List<ChatAdvisor> advisors = new ArrayList<>();
        if (toolCallEnabled) advisors.add(new ToolCallAdvisor());
        if (memoryEnabled) advisors.add(MessageChatMemoryAdvisor.builder()
            .chatMemory(ChatMemory.empty())
            .build());
        // ... 其他 Advisor
        return advisors.toArray(new ChatAdvisor[0]);
    }
}
```

## 五、架构冲突预防指南

### 5.1 构建系统兼容性

**问题**：Gradle → Maven 转换时构建脚本差异

**预防措施**：
- 保持 Java 代码完全兼容，不依赖 Gradle 特定功能
- 使用标准 Maven 坐标管理依赖
- 测试使用 Maven Surefire，不依赖 Gradle Task

### 5.2 Spring Boot 版本兼容性

**问题**：Spring Boot 4.0 与 3.x 的 breaking changes

**预防措施**：
- 保持 Spring Boot 3.5.8 直至 Spring AI 2.0 完全适配
- 或等待 `spring-ai-alibaba-starter` 支持 Spring Boot 4.0

### 5.3 数据库迁移策略

**问题**：ddl-auto update vs Flyway 版本化管理

**预防措施**：
- ai-interview 使用 Flyway，保持现有迁移脚本
- interview-guide 的 JPA Entity 可直接迁移为 Flyway 迁移脚本
- 避免在 Entity 中使用 `ddl-auto` 特有注解

### 5.4 AI Provider 切换

**问题**：单一 Provider 切换到多 Provider 的数据迁移

**预防措施**：
- 设计数据库配置表时预留 `provider_id` 字段
- 现有配置迁移为默认 Provider
- 实现灰度切换机制
